# Optimization review

## Result
Move six private constant offset tables from per-call initialization to class initialization.

Decision: retain with the reviewed maintainability refactors.
Modernization commit `de52df5d8c0c60f2491376f9618d3f16551b62f0` is pushed to `origin/master`; the remote hash was verified. The optimization is included with the subsequent reviewed maintainability changes. Temporary measurement output is excluded from commits.

## Ablation method
Baseline `de52df5` is extracted from Git into a temporary directory and compiled with an independent assembly name. The runner compares that implementation with the candidate in the same process. Only one optimization is enabled per repository. No combined improvements mask an individual contribution.
Run `python3 verification/run-ablation.py` from this repository. Requires Git, Python 3.12+, and .NET SDK 10.0.401.
Every case has 10,000 warmup calls and nine alternating baseline/candidate batches. Each result records its batch size and all raw timings in the ignored `verification/results.json` generated by the runner. Trials were run sequentially across repositories with `DOTNET_TieredCompilation=0` to avoid tier-transition and inter-study interference.
Runtime: .NET 10.0.12; architecture: Arm64. Medians measure the fitness/helper call workload, including identical input resets where mutation requires them. These are local microbenchmark results, not whole-application speedups. No claim is made about other hardware or default tiered-runtime performance.

## Numerical evidence
186,000 bit-exact comparisons passed. Maximum observed absolute and relative difference for finite outputs: **0**, stricter than the proposed 1e-12 ceiling.
Pinned Git baseline; one allocation optimization; nine alternating trials after warmup. Compare fitness and input mutation exactly. Existing shifted-sphere formula behavior is preserved.
Input/state checks are included where the evaluated method mutates positions; allocation changes do not alter formulas, bounds, quantization, or random draws.

## Limits and findings for review
The optimized .NET 10 JIT already eliminates heap allocations for these constant literals in this measurement mode: bytes per call did not decrease. The measured benefit is reduced repeated initialization work, not an observed heap-allocation reduction.

The pre-existing function 100 shifted-sphere code subtracts its offset into the position but accumulates the unshifted coordinate squared. The comparison intentionally preserves this behavior; it proves equivalence, not compliance with the CEC 2005 shifted-sphere definition. Correcting that formula requires a separate behavioral change and fresh baselines.
The six affected shifted objective functions were each tested with 1,000 inputs; other objective functions and optimizer update formulas were not modified. Full optimizer trajectories were not separately compared for these repositories.
